# 결정 기록

정한 것, 미룬 것, 뺀 것을 날짜와 함께 한 줄씩 적는다. 미룬 결정을 미뤘다고 적어 두면 나중에
그것이 빚인지 판단인지 구분된다.

## 2026-10-05

### 정한 것
- 계산은 코드가, AI는 해석만. 확률·숫자는 `core/`의 순수 함수가 낸다
- 엔진은 Python, 서비스는 FastAPI. 강의 스택(LiteLLM·Docker)과 그대로 이어진다
- 범위는 세계를 국가 단위로 먼저(World Bank, 키 불필요). 한국 상세(시도·직업·소득 분위)는 v0.3
- 첫 AI 자리는 인생 서사 생성. 조회할 것이 미리 정해지므로 루프는 ReWOO
- 데이터는 파일(json)로 시작한다. DB는 규모가 근거를 줄 때
- 원본은 `data/raw/`(gitignore), 받는 방법은 `scripts/`. 정제 결과만 커밋
- 통계가 없으면 0이 아니라 "데이터 없음"(None)
- 화면은 정적 HTML 한 장. 프레임워크는 v0.5 이후에 판단
- 릴리스 브랜치 이름은 저장소가 시작한 `master`를 그대로 쓴다

### 미룬 것
- 한국 시도별 출생·직업 분포 — KOSIS 키 또는 수동 다운로드가 필요. v0.3
- 성인 키(NCD-RisC) — 국가·성별 평균만 있어 분포 가정이 필요. v0.3 이후
- 부모의 이혼 — 한국 통계로 근사 가능하나 가정이 큼. v0.3 이후
- 배포 대상(Render 등)과 공유 URL — 12주차
- 애드센스·후원 버튼 — github.io 기본 도메인은 승인이 어렵다고 알려져 있음. v1.0 이후

### 뺀 것
- MBTI — 신뢰할 만한 인구 분포 통계가 없다
- 동성 부모 — 국가별 통계 공백이 커서 확률로 말할 수 없다
- 질병 유무 — 출생 시점의 결합 통계가 없다
- "3차원 벡터 변환" — 범주형 확률표라 임베딩이 필요 없다. 벡터는 문서 검색(RAG)을 할 때만

## 2026-10-06 (v0.5)

### 정한 것
- 첫 모델은 Gemini(`gemini/gemini-3.5-flash-lite`, Google AI Studio). 모델은 `NARRATOR_MODEL` 한 줄로 바꾼다
- 부르는 곳이 하나라 게이트웨이(LiteLLM proxy)는 두지 않는다. 앱이 LiteLLM 라이브러리로 직접 부른다(8주차)
- 구조화 출력은 instructor 대신 "스키마를 도구로 등록하고 tool_choice로 강제"(5주차 방식 3). 의존성 하나를 덜 늘린다
- 뽑기는 늘 템플릿 서사로 즉시 답하고, AI 서사는 버튼으로 따로 부른다. 비용과 3~5초 지연은 원할 때만
- 서사 검증은 숫자만 본다(근거에 없는 숫자, 사망 사례의 사망률 누락). 문체·고정관념은 프롬프트 규칙과 사람 평가로
- 프로세스 누적 예산 `STORY_BUDGET_USD`(기본 $0.50). 서사 1건이 약 $0.002라 수백 건을 견딘다
- 테스트는 실제 모델을 부르지 않는다(각본 LLM). 실제 품질은 `scripts/eval_stories.py`로 잰다

### 알게 된 것
- LiteLLM의 재시도(`num_retries`)는 `tenacity`가 있어야 돈다. 없으면 일시 장애가 곧바로 실패가 된다
- Gemini 무료 티어는 분당 요청 한도가 있어 연달아 부르면 429. 평가 스크립트는 사이에 쉰다
- 스키마의 `title` 메타데이터를 지우다 `title`이라는 필드까지 지우면 Gemini가 400으로 거부한다

### 평가 결과 (reports/story_eval.md, 시드 1000~1009)
- 10/10이 AI 서사로 나갔고 10/10이 첫 원고에 숫자 검증을 통과했다. 건당 평균 $0.0017, 4.7초
- **숫자 검증의 한계가 실물로 나왔다.** 근거에 있는 숫자를 틀린 뜻으로 쓰면 못 잡는다
  - 시드 1001: 나라의 연간 출생아 수(893,539)를 제목에서 확률처럼 씀("893,539분의 우연")
  - 시드 1002: 브라질의 출생아 수를 "이 해에 세상에 태어난 아이"로 씀
- 조회한 세계 비교(배율·순위)를 잘 쓰지 않아, 템플릿보다 정보가 크게 늘지 않은 서사가 많다
- 그래서 "숫자는 맞다"는 보증까지만 하고, "뜻도 맞다"는 아직 사람이 읽어 판정한다

### 미룬 것
- 숫자의 뜻 검증 — 서사가 쓴 숫자마다 어떤 사실 키에 기댔는지 구조로 받고(문단 + 인용 키), 코드가 키와 값의 짝을 대조한다
- 사용자별 요청 수 제한(공개 배포 시 필요) — 12주차 배포와 함께
- 문체·톤의 자동 채점(Reflexion 루브릭) — 사람 평가로 기준을 먼저 세운 뒤

## 2026-10-06 (v0.6 한국 상세 — 처음 로드맵의 v0.3)

### 정한 것
- 한국 칸은 시도 · 어른이 되어 일하는가 · 직업(대분류) 셋. 대한민국에서 태어났을 때만 열린다
- 시도는 2025년 출생아(성별), 고용은 2025년 하반기 고용률(시도·성별), 직업은 2020년 인구총조사(시도·성별)
  — 성별이 있는 시도별 직업 표가 인구총조사뿐이라 연도가 어긋나는 것을 감수한다
- 다섯 살을 맞지 못하면 고용·직업 칸이, 일하지 않으면 직업 칸이 없다. "데이터 없음"과 "해당 없음"을 가른다
- 난수는 일곱 번 쓰고 앞의 넷은 그대로 — 예전 공유 링크가 같은 국가·성별·생존·경제를 낸다(2만 개 시드로 확인)
- 시도 칸 이름은 `province`. 기존 `Country.region`(World Bank 지역)과 헷갈리지 않게
- 화면의 app.js 주소에 날짜를 붙인다. 배포 뒤에도 브라우저가 예전 파일을 쓰지 않게

### 가정 (docs/probability-model.md)
- 5세 이후 성인이 될 때까지의 사망은 모델에 없다
- 태어난 시도에서 산다고 본다(이사 없음)
- 고용률은 15세 이상 전체의 값이라 한창 일할 나이의 고용률보다 낮다

### 미룬 것
- 소득 분위 — 시도별로 쓸 만한 KOSIS 표를 찾지 못했다
- 시군구 — 출생 표에는 있지만 고용·직업이 시도까지라 체인이 끊긴다

### AI 서사에서 본 것
- 연도(2025)를 사람 수("2,025명")로 쓴 원고가 숫자 검증을 통과했다 → 연도와 값을 따로 대조하게 고쳤다
- 전국 출생아 수를 "전북에서 태어난 242,917명"으로 쓴 원고는 여전히 통과한다. 같은 종류의 뜻 오류다
- 어른이 된 뒤의 칸(고용·직업)을 서사가 자주 빠뜨린다. 템플릿 서사는 빠짐없이 쓴다

## 2026-10-11 (1in8b 벤치마크 반영)

### 결측 규칙 (확인하고 유지)
- 코드의 규칙을 기준으로 삼는다: 통계가 없으면 `None` → 화면 "통계 없음", 역확률은 `coverage`.
  지역 평균 같은 대체값으로 메우지 않는다.
- 예외 둘은 유지하되 '추정' 배지로 드러낸다: 출생 성비가 없으면 1.05, 성별 사망률이 없으면 남녀 합계.
  2026-10-05 스냅샷에서는 둘 다 쓰인 적이 없다(0개국·0건).
- `개발 방향.md`의 "상위 수준 분포로 대체"는 구현된 적이 없는 초안이라 이 규칙으로 고친다.

### 근거 표시 (feature/source-badges)
- 모든 칸이 기준 연도(`year`)와 가정 한 문장(`assumption`)을 싣는다. 화면은 연도·추정·통계 없음 배지와
  접어 둔 가정 설명으로 보여 주고, 역확률 풀이에도 칸별 출처를 붙인다.
- 가정 문장은 `core/model.py`의 `NODE_ASSUMPTIONS`에 둔다. `probability-model.md`와 짝이다.

### 체감 단위 (feature/one-in)
- 칸마다 "N명 중 1명", 국가는 "한 해 약 N만 명, 1분에 약 N명 / 약 N분에 1명"을 함께 쓴다. 값은 `core/units.py`가 낸다.

### 출생 코호트 안의 위치 (feature/cohort-position)
- 한 사람마다 위치 한 줄: 무엇을 말할지는 `choose_headline` 규칙(사망 → 경제 → 생존 → 없음)이 정하고 테스트로 지킨다.
  1in8b가 37년 일한 삶을 61세에 잠깐 한 일로 요약한 사례(벤치마크 6장 6번) 같은 오류를 막으려는 규칙이다.
- "같은 해 태어난 아이 중"이라고 말하지 않는다. 스냅샷은 출생 연도 코호트가 아니라 나라마다 최근 통계다.
- 세계 비율은 통계가 있는 나라의 출생아만 대상으로 하고 그 비율(`coverage`)을 함께 보여 준다.

### 같은 순간 태어난 다른 4명 (feature/same-moment)
- 본 인생과 따로 문자열 시드에서 뽑아 기존 시드 재현성을 지킨다. 4명은 세계에서 뽑고(국가 고정과 무관), 각자 시드 링크가 있다.

### 내 실제 나라와 나란히 (feature/home-compare)
- 비교할 때마다 내 나라를 API로 보내는 대신, 모든 나라 지표(`/api/profiles`)를 한 번 받아 브라우저에서 고른다.
  선택은 `localStorage`에만 두고, 서버로 가는 요청에 실리지 않는 것을 브라우저로 확인했다.
- 두 값을 나란히 보여 주기만 한다. 차이·배율은 화면에서 계산하면 '숫자는 core가 낸다'를 어기고, 모든 쌍을 미리
  계산하기에는 과해서 넣지 않는다.

### 하지 않은 것 (벤치마크 5장 '원칙과 충돌')
- 지역 평균으로 결측 채우기, 근거 없는 0~100 상태값, 근거 없는 선택 효과, 뽑지 않은 픽션 사건, 추모·애도 장치.

### AI 서사를 해석가로 (feature/ai-interpreter)
- 문제: AI 서사가 템플릿을 말만 바꿔 다시 썼다. 평가 10건에서 AI 숫자의 약 75%가 템플릿에도 있었고,
  템플릿과의 글자(3글자 단위) 겹침이 19~42%, 세계·이웃 조회를 실제로 쓴 글은 10건 중 2건이었다.
- 원인: 같은 사실 목록을 재료로 받았고, 템플릿 자리를 덮어썼고, "새로운 걸 말하라"를 강제하는 규칙이 없었다.
- 바꾼 것: AI는 템플릿 아래 "AI 해석"으로 덧붙인다. 재료는 화면에 없는 근거(세계 비교·이웃 나라·같은 순간 4명).
  화면 글을 함께 주고, 겹침 35% 이하와 새 근거 2개 이상을 코드로 검증한다. 순위는 방향을 밝히고, 이웃 나라 평균과
  같은 순간의 사람을 섞지 않게 했다.
- 결과(같은 시드 10건): 첫 원고 통과 10/10, 화면 글과 겹침 평균 14%, 화면에 없던 근거 평균 8개, 건당 $0.0020.
- 남은 것: 뜻 검증은 여전히 사람이 읽어서 한다. 사망 사례의 해석은 대비가 강해 톤을 계속 지켜봐야 한다.
- 사망 사례에 사망률을 반드시 쓰게 하던 규칙은 뺐다. 템플릿이 늘 보이므로 해석에서 되풀이할 이유가 없다.

### AI 해석: 숫자는 참조로 (feature/ai-references, 13주차 라이브 빌드 3)
- 문제: 숫자는 근거에 있었지만 뜻이 틀렸다 — 세계 평균을 그 나라 값처럼, 기대수명 순위를 극빈율 문장에,
  높은 쪽 순위를 "낮은 쪽에서"로, 사망 수를 "살아남은 수"로 썼다.
- 바꾼 것: 해석가는 숫자를 쓰지 않고 `{R#}`로 가리킨다. 값은 코드가 채운다. 목록에 뜻을 붙이고, 순위 방향과
  나라 수는 값과 함께 채워 뒤집을 수 없게 했다. 비교 값은 지표·나라 이름이 같은 문장에 있어야 살아남는다.
- 검사 단위는 문장 하나다. 원고 전체를 버리고 다시 쓰게 하던 것을, 걸린 문장만 지우고 남은 글이 기준(겹침 35% 이하,
  새 근거 2개 이상)을 넘으면 그대로 내보낸다. 훈계·운 평가 말(`BANNED`)도 같은 방식으로 지운다.
- 의존성 추가 없음. `Narrator` 시그니처 그대로. `/api/story`의 `violations`는 `dropped`('이유 | 문장')로 바꿨다.
- 결과(시드 1000~1009): 첫 원고 통과 10/10, 버린 문장 1, 겹침 18%, 새 근거 6.3개, 건당 $0.0020.
  같은 10건을 사람이 읽었을 때 숫자의 뜻이 틀린 문장은 없었다. 글이 지표를 나열하는 쪽으로 단조로워진 것은 남은 문제다.

### AI 해석 캐시: 시간 말고 버전으로 (feature/ai-references, 13주차)
- 같은 시드를 다시 누르면 같은 해석을 돌려준다. 키는 데이터 지문 · 프롬프트(계획자·해석가·도구 설명) 지문 · 모델.
  통계를 다시 받거나 프롬프트를 고치면 자연히 새로 만든다. TTL은 두지 않는다 — 시간이 지났다고 답이 틀려지지 않는다.
- 성공한 해석만 기억한다. 실패(템플릿)는 다음에 다시 해 본다. 프로세스 메모리 LRU 512건 — 배포 인스턴스가 하나라
  외부 저장소는 아직 필요 없다. 실측: 같은 요청 4.2초·$0.0021 → 0.003초·$0.
- 계획자 도구 설명에 "쓰지 않을 때"를 한 줄씩 붙였다(13주차: 모델이 고르고 코드가 실행).

### 화면도 계산기 순서로 (feature/calculator-first, v1 2단계)
- 섹션 순서: 이렇게 태어날 확률 → 될 때까지 다시 태어나기 → 다시 태어나기. 첫 줄 소개와 `<title>`도 계산기 문장으로.
- '될 때까지'는 확률 결과 안의 버튼이었는데 독립 섹션으로 꺼냈다. 위 확률 섹션에서 고른 조건을 그대로 쓰고,
  고른 조건을 글로 보여 준다. 조건이 없으면 돌리지 않는다. API(`/api/until`)는 그대로다.
